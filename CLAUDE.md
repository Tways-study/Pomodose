## Commands

```bash
npm run dev         # start dev server (localhost:3000)
npm run build        # production build
npm run lint         # eslint (flat config, eslint-config-next)
npm run typecheck    # tsc --noEmit
npm test             # vitest run (single run, used in CI)
npm run test:watch   # vitest watch mode
```

Run a single test file: `npx vitest run lib/dosey.test.ts`
Run tests matching a name: `npx vitest run -t "includes the dose count"`

CI (`.github/workflows/ci.yml`) runs lint → typecheck → test → build in that order on every push/PR to `main`. Match that order locally before pushing.

## Architecture

This is "Apothecary" (package name `pomodose`), a single-page Pomodoro timer + daily goal tracker + AI chat companion ("Dosey"), themed around a pharmacy and built for pharmacy students first (licensed pharmacists welcome too). Empty goal lists show example student goals from `lib/goal-examples.ts`. It's a personal single-user gift app, not multi-tenant SaaS — login/register is a personal access gate, not account infrastructure for many users (see `PRODUCT.md`). The main app lives on one route (`app/page.tsx`); the only other routes are `app/login/page.tsx` and the `app/api/chat/route.ts` API route. `app/error.tsx` is a themed client-side error boundary (Next's `error.tsx` convention) for uncaught render errors, not a route.

**This Next.js version has real breaking changes from training-data Next.js — read `AGENTS.md` before touching routing/middleware.** Concretely: there is no `middleware.ts`; route gating lives in `proxy.ts` at the repo root and exports `proxy` (not `middleware`). Check `node_modules/next/dist/docs/` for anything else that looks off versus what you expect.

**Auth and goal persistence run on Convex** (`convex/`), not localStorage. `convex/schema.ts` defines `goals` and `sessions` (both indexed `by_user_and_date`) alongside `@convex-dev/auth`'s `authTables`. `convex/auth.ts` configures a **password** provider — no email verification on signUp/signIn, so accounts are created and signed in immediately (server-side email format re-validation happens in `validateEmail` since the mutation is reachable directly, bypassing the client's `<input type="email">`). Password reset is scaffolded via `convex/BrevoOTPPasswordReset.ts` (a Convex Auth `Email` provider passed as `Password`'s `reset` option, calling Brevo's transactional email API directly over `fetch()` — `POST https://api.brevo.com/v3/smtp/email` — to email a short numeric OTP) — it's wired end-to-end through `Password`'s native `"reset"`/`"reset-verification"` flows, but reads `BREVO_API_KEY`/`BREVO_SENDER_EMAIL` lazily and throws the distinct `"Password reset is not configured yet."` error if either is unset on the deployment yet (`npx convex env set BREVO_API_KEY <key>` etc. once a real Brevo API key and verified sender email exist). `convex/goals.ts` mutations/queries all call `getAuthedUserId` (`convex/lib/auth.ts`) and check row ownership before mutating. **`convex/_generated/` is committed to git** (see the "Commit convex/_generated/" commit) so CI can typecheck Convex code without running `convex dev`/`codegen` first — regenerate and commit it after schema/function changes. Client-side, `app/ConvexClientProvider.tsx` wraps the app in `ConvexAuthNextjsProvider`, and `proxy.ts` redirects unauthenticated requests to `/login` (JSON 401 for `/api/*`).

**Journal.** The right column's "Journal" card (`components/journal-card.tsx`) keeps the rotating `QuoteCard` as a writing prompt and adds one autosaved entry per day. `convex/schema.ts`'s `journal` table (indexed `by_user_and_date`) is upserted by `convex/journal.ts`'s `save` (empty text deletes the row; the 2000-char cap lives in `lib/journal.ts` and is enforced client- and server-side). The component's `draft` stays `null` until the first keystroke, then owns the text so a late query result can't clobber typing; past days are read-only.

**State lives in `app/page.tsx` and flows down, except goals.** The timer is a `useReducer` over `lib/timer-machine.ts`, held in page state — phase/status/remaining are **not** persisted and reset on reload. `dailyDoses`/`focusCycle` are the exception: `components/vial-timer.tsx` logs each completed session via `api.sessions.log` (`convex/sessions.ts`), and `app/page.tsx` seeds the reducer once from `api.sessions.listForDate` through the `HYDRATE` action on the first resolved query (after that the reducer owns the counters, so a slow/offline write can't clobber a fresh count). Goals are a Convex live query owned by `components/goal-list.tsx` (and independently re-queried by `components/dosey-chat.tsx` for chat context); `goal-list.tsx` reports aggregate done/total counts up to the page via an `onProgressChange` callback. There is no global store for timer/goal state — if a component needs timer state, it must be passed as props from the page; goal state is fetched directly wherever it's needed via `useQuery(api.goals.*)`. The one exception is `components/address-term-provider.tsx`, a context that picks a random address term (e.g. "Pill Whisperer") for how the app refers to the user; it defaults to a deterministic index-0 value and randomizes only in a post-mount `useEffect` to avoid a server/client hydration mismatch — follow that pattern for any future randomized-on-load UI.

**Timer is timestamp-driven, not tick-decremented.** `lib/timer-machine.ts` is a pure reducer keyed on `Date.now() + startedAt`; `remaining` is recomputed from the elapsed wall-clock time on every `TICK`, not decremented by 1 each second. This keeps the countdown accurate when the tab is backgrounded/throttled. Any change to timer logic must preserve this invariant (see the existing tests in `lib/timer-machine.test.ts`).

**Goals are scoped by a client-computed `date` field, not server-side rollover.** `lib/date.ts`'s `todayKey()` produces `YYYY-MM-DD`; `goal-list.tsx` queries `api.goals.list` for today's key, so switching days just queries a different (empty) bucket — old goals aren't deleted, they simply stop showing. The 80-char text cap is enforced both client-side (`goal-list.tsx`'s `<input maxLength={80}>`) and server-side (`convex/goals.ts`'s `MAX_GOAL_TEXT_LENGTH`), since the mutation is reachable directly, bypassing the form.

**Dosey (AI chat) is a thin proxy to Gemini, not a stateful backend.** `app/api/chat/route.ts` is the only API route: it Zod-validates `{ messages, stats, goals }` from the client, applies a per-IP daily rate limit (see below), builds a system instruction from `lib/dosey.ts` (persona + `buildContextBlock`, which renders the live timer/goal snapshot as text), and streams `@google/genai`'s `generateContentStream` output back as a raw text stream (no SSE framing — the client reads the stream directly). Requires `GEMINI_API_KEY`; the route returns a 500 with a user-facing message if it's missing rather than throwing. `components/dosey-chat.tsx` owns chat message history client-side and re-sends the full history + current stats/goals on every message — the server is stateless per request. `lib/chat-history.ts`'s `trimHistory` caps what's sent/kept to the most recent messages and is used both client- and server-side.

**Chat rate limiting is in-memory and per-server-instance, by design.** `lib/rate-limit.ts` splits a pure decision function (`evaluateRateLimit`, unit-testable like `timerReducer`) from a stateful `Map`-backed wrapper (`consumeRateLimit`) — the module comment explains this resets on redeploy/restart and isn't a global quota on serverless multi-instance hosting, which is accepted for this project's scale. `lib/rate-limit-storage.ts` mirrors the "resting until" state into `localStorage` purely so the client UI can show/hide the composer without a request; it's not the source of truth.

**Types are centralized in `types/index.ts`**, not colocated with modules: `Phase`, `TimerStatus`, `TimerState`, `Goal`, `ChatMessage`, `DoseyStats`, `DoseyRateLimitState`, `ChatRateLimitError`. When adding a field to timer or goal state, update this file first, then the Zod schemas that mirror it (`app/api/chat/route.ts`'s `statsSchema`/`goalSchema`) and the Convex validators in `convex/schema.ts`/`convex/goals.ts` — these are hand-kept in sync with the TS types, not generated from them.

**Design tokens live only in `tailwind.config.ts` ("Gelcap Pastel" world).** Colors: `ground` (peach page), `surface`/`surface-2` (cards, nested rows/inputs), `ink`/`ink-soft` (text; `ink-soft` on surfaces only), `line-soft` (decorative edges) / `line-strong` (control borders), `alert`, the `gum-*` stickers (`sky` focus, `mint` short break + done, `apricot` long break + warnings, `butter` nudges, `rose` remove/undo, `lilac` Dosey/chat; text on every gum is `text-ink`) and the `dosey-*` mascot colors. Radii: `rounded-bubble` (28px cards/modal), `rounded-control` (18px inputs/rows), `rounded-pill`. Shadows: `shadow-soft`/`pop`/`gum` (there is no `shadow-label`). z-index: `z-content/sticky/overlay/modal`. Fonts: `font-display` (Fredoka: headings, buttons, numbers) and `font-body` (Nunito); sentence case, no monospace, no Inter/Roboto/Arial. `globals.css` adds the `digits` utility (tabular Fredoka), `dots-divider`, the global 3px `ink` focus ring and themed `::selection`/scrollbar. No hardcoded hex in components; hex lives only in `tailwind.config.ts`, `layout.tsx`/`manifest.ts` theme colors and `lib/phase-theme.ts`. Spring presets (`SPRING_UI`/`SPRING_SOFT`/`SPRING_BOUNCY`) and GSAP ease/`REVEAL` constants live in `lib/motion.ts`. Icons are `lucide-react` (16 inline / 20 controls, stroke 2.25, `aria-hidden`); the vial timer and Dosey stay custom. `PRODUCT.md` covers brand voice; `DESIGN.md` has design rationale.

**The vial timer (`components/vial-timer.tsx`) is the signature UI element** — an SVG vessel (flask, or graduated cylinder via the vessel toggle) whose liquid is a full-height `<rect>` clipped to the glass and animated with Framer Motion `scaleY` (transform-based, origin at the bottom), where `remaining/total` sets the scale (focus drains; breaks fill). It is intentionally not a circular progress ring; do not replace it with one. The flask vessel is drawn in three.js (`components/three/flask-3d.tsx`, lazy via `FlaskSlot` in `scenes.tsx`; pure geometry/slosh/bubble/splash math in `lib/three/flask.ts`): lathe glass, a liquid wall clipped by a world-space plane, a wavy surface disc, rising bubbles, idle sway while running and a droplet splash on completion (`VialTimer` bumps `splashKey`). The SVG flask stays underneath and is only removed once the 3D scene reports its first frame (`onStatus`), so reduced motion / no WebGL2 / a lost context fall back to the SVG; the cylinder vessel is SVG only. The liquid is fixed `dosey-lilac` and is **not** driven by phase colors. The time readout (`digits` utility) is printed one fixed-width soft rounded `surface-2` cell per character so digits never jitter.

**Phase color is a sticker, not chrome.** `lib/phase-theme.ts` exports `PHASE_STICKER_CLASS` (Tailwind classes: `bg-gum-sky text-ink` focus, `bg-gum-mint text-ink` short, `bg-gum-apricot text-ink` long) — use it wherever a phase color is needed (e.g. the phase sticker on the timer card in `app/page.tsx`). There are no washes, bubbles or running glows; never hardcode hex.

**Motion split: GSAP owns scroll and the mascot, framer owns micro-interactions.** Framer springs: `SPRING_UI` (press/hover), `SPRING_SOFT` (panels), `SPRING_BOUNCY` (button press-boing via `whileTap={{ scale: 0.94 }}`). `lib/gsap.ts` exports `gsap`, `ScrollTrigger`, `useGSAP` and `withMotion(setup)` (a `gsap.matchMedia` gated on `prefers-reduced-motion: no-preference`; initial hidden states are set only inside it, so content is visible with reduced motion or before JS; callers revert the returned MatchMedia). `components/scroll-reveals.tsx` (`ScrollReveals({ scopeRef, refreshKey })`) creates a one-shot reveal per `[data-reveal]` section in the right column and staggers `[data-reveal-item]` children; `data-reveal="none"` opts out; `refreshKey` (goal count) triggers `ScrollTrigger.refresh()`. Never animate one element with both libraries, and never target the same element with two GSAP timelines (the Meet Dosey card scrubs its inner mascot parts; the outer section only fades/slides in).

**Dosey mascot.** Drawn to the ip-as-logo rules: flat, outline-free, blunt rounded shapes (lilac dome, cream bottom, two plump leaves, one tomato), ink dot eyes set wide, blush cheeks, always upright; colors only from the `dosey-*` tokens and `ink`. `components/dosey/dosey-rig.tsx` (`DoseyRig({ mood, size, interactive, onPoke, variant, trackPointer })`) is the GSAP-rigged SVG with three variants: `full` (whole capsule), `face` (lilac head + bare sprout) and `peek` (head cropped flat at the bottom). With no `variant` it auto-picks `face` below size 40, which also renders a static pose (no idle loops); cheeks drop below 28. `components/dosey/dosey-peek.tsx` (`DoseyPeek({ mood })`) is the decorative head-only `peek` that sits over the top edge of the timer card in `app/page.tsx`. The mascot is also the brand mark (header, login). `components/dosey/use-pointer-eyes.ts` tracks the pointer for interactive/`trackPointer` rigs. `components/dosey/use-dosey-mood.ts` (`useDoseyMood(phase, status)`) derives a mood via `lib/dosey-mood.ts` and needs `NotificationProvider` context, so `app/page.tsx` wraps consumers in `ConnectedDoseyPeek` and `ConnectedDoseyChat` (rendered inside the provider); `lib/dosey-lines.ts` holds the mood/poke speech lines. `components/dosey/meet-dosey.tsx` is the page's "Meet Dosey" card (loaded with `next/dynamic`, `ssr: false`, placeholder of equal min-height); its stage clips the capsule emerging cropped from the lower-left corner (`overflow-hidden`, mascot offset negative bottom/left). Chat open state is lifted to the page: `DoseyChat` takes controlled `open`/`onOpenChange` plus a `mood` prop, and Meet Dosey's "ask" button opens it.

**Dosey motion.** Moods are `sleepy | focused | relaxed | proud | waiting` (paused = `waiting`). `lib/dosey-motion.ts` is the pure logic (`momentFor` picks the one-shot reaction to a mood change, `registerPoke` detects the 3-poke dizzy combo, `DOSEY_TIMING` holds loop timings; deep-sleep delay is `SETTINGS.DOSEY_DEEP_SLEEP_SECONDS`). The rig is SVG + wiring; motion lives in hooks: `use-dosey-idle.ts` (blink, breathe, per-mood loops, fx, deep sleep; IntersectionObserver-gated), `use-dosey-moments.ts` (finite moments, poke, dizzy; its own gsap context so idle re-runs never revert it) and `use-hover-lean.ts`; timeline builders are in `dosey-timelines.ts`/`dosey-fx-timelines.ts`. Every SVG group has exactly one tween owner, nested `lean` (hover) > `squash` (poke) > `react` (moments/dizzy) > `move` (idle) > body, leaves `sway` (idle) > `perk` (moments/poke), and each eye's `gaze` group (scripted glances; pupil x/y belong to `use-pointer-eyes`). `peek` never translates in y (scaleY stretches). Size tiers: below 40 only blink, finite moments and the chat `thinking` gaze; fx (Zzz, sparkles, breeze) only for `full`/`peek` at size 56+. All of it runs inside `withMotion`, so reduced motion is a static per-mood pose.

**Header menus.** The header holds a profile bubble and a gear, both built on `components/header-popover.tsx` (`HeaderPopover`: a non-modal disclosure panel — Escape and outside press close it, focus returns to the trigger, and a layout effect nudges the panel back inside the viewport on phones). `components/settings-menu.tsx` (the gear) holds `ChimeVolume`, `OsNotificationToggle` and the Help and tips row; it closes itself first so the help dialog hands focus back to the gear. `components/profile-menu.tsx` shows the signed-in email from `convex/users.ts`'s `me` query (null when signed out, so it never throws mid sign-out) and owns Sign out; the query runs inside `components/silent-boundary.tsx`, so a missing or failing `users.me` degrades the bubble to a generic "Account" label while Sign out keeps working. The footer is only the quote line and the version.

**Primary action and mobile bar.** `lib/primary-action.ts` is the pure resolver for the timer's primary button (label/intent per state); `components/sticky-timer-bar.tsx` is the mobile sticky timer bar shown when the Rx label scrolls out of view (framer-driven).

**Notifications are a pure-heuristic + provider layer.** `lib/settings.ts`'s `SETTINGS` holds every duration and burnout threshold (focus/break lengths, `CYCLE_LENGTH`, nudge timers, late-hour window) — change numbers there, not inline. `lib/burnout.ts`'s `detectBurnout` is pure (`now` is passed in, never read from `Date.now()`) and returns the single highest-priority hit. `components/notification-provider.tsx` turns events into copy from `lib/notification-copy.ts` (rotating variants; `ADDRESS_TOKEN` is substituted with the address term), the on-page counter note, tab-title flash, and optional OS notifications (`lib/os-notification.ts`). Add new event types to `NotificationEvent` in `types/index.ts` and `NOTIFICATION_PRIORITY`.

**Completion alert and tab title are side-effectful modules that must be explicitly stopped.** `lib/chime.ts` exports `startCompletionAlert()` (rings a bell immediately, then every 4 s) and `stopCompletionAlert()` (must be called whenever the user takes any action: phase tab switch, timer reset, starting a new session — `PhaseTabs`'s `onChange` already calls it). `lib/document-title.ts` manages three states: live countdown via `setRunningTitle(phase, remaining)` on every tick, `flashCompletionTitle()` on session end (flashes the tab title only when the tab is hidden), and `resetTitle()` on idle. Both modules guard `typeof document === "undefined"` so they're SSR-safe.

## Constraints from the original build spec

These still apply:

- No `any` in TypeScript; no empty `catch` blocks.
- Respect `prefers-reduced-motion` in animated components (see the reduced-motion fallback in `quote-card.tsx`).
- Restraint over feature bloat — one concern per file, no unrelated additions.
