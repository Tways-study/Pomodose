# Pomodose

<hr width="50%">

*"Rest is part of the prescription, not a break from it."*

A Pomodoro timer, daily goal tracker, and AI study companion — built as a gift for a
pharmacist grinding through long solo study sessions, so the work feels structured,
measured, and a little less lonely. Work sessions are "Doses," breaks are "Refills"
and "Antidotes," and Dosey — the study companion — is on hand to talk through progress.

Everything lives on a single page (`app/page.tsx`); there's no routing beyond authentication and the chat API.

## Features

- **Timer** — a timestamp-driven Pomodoro timer (`lib/timer-machine.ts`) visualized as a liquid-filled vial, with a Flask / Graduated Cylinder vessel toggle (`components/vial-timer.tsx`). Sessions stay accurate even when the tab is backgrounded.
- **Goals** — a daily goal list backed by Convex, rolling over at local midnight. Includes example goals for pharmacy students via `lib/goal-examples.ts`.
- **Dosey** — an AI chat companion (`components/dosey-chat.tsx`) powered by Gemini, aware of your live timer and goal state. Interactive mascot with mood-driven reactions (`components/dosey/`) and speech variants (`lib/dosey-mood.ts`, `lib/dosey-lines.ts`).
- **Auth** — password-only email/password sign-in via Convex Auth, with optional OTP-based password reset via Brevo. No email verification required for signup.
- **Notifications** — OS-level desktop notifications, burnout detection, and smart nudges for skipped breaks and long unbroken study stretches (`lib/burnout.ts`, `components/notification-provider.tsx`).

## Getting Started

### Prerequisites

- A [Convex](https://www.convex.dev) deployment (`npx convex dev` to set one up)
- A [Gemini API key](https://ai.google.dev/) for Dosey

### Environment variables

Create `.env.local` with:

```bash
CONVEX_DEPLOYMENT=
NEXT_PUBLIC_CONVEX_URL=
NEXT_PUBLIC_CONVEX_SITE_URL=
GEMINI_API_KEY=
BREVO_API_KEY=           # optional, for password reset via email OTP
BREVO_SENDER_EMAIL=      # optional, for password reset via email OTP
```

`CONVEX_DEPLOYMENT` / `NEXT_PUBLIC_CONVEX_URL` / `NEXT_PUBLIC_CONVEX_SITE_URL` are generated by `npx convex dev`. The Brevo variables are optional; without them, password reset is disabled and the app returns a user-friendly error message.

Convex Auth needs its signing keys (`JWT_PRIVATE_KEY`, `JWKS`) and `SITE_URL` set directly on the Convex deployment (these are per-deployment, not read from `.env.local`). Generate the keys with:

```bash
npx @convex-dev/auth        # sets JWT_PRIVATE_KEY + JWKS on the deployment
npx convex env set SITE_URL "http://localhost:3000"   # your app's origin
```

> **Deploying to production:** env vars are per-deployment, so repeat the auth-key
> and `SITE_URL` setup against the prod deployment (`npx @convex-dev/auth --prod`,
> and `SITE_URL` = your deployed URL), then push functions with `npx convex deploy`.

### Run the app

```bash
npm install
npx convex dev      # in one terminal, keeps Convex functions in sync
npm run dev          # in another terminal
```

Open [http://localhost:3000](http://localhost:3000).

```bash
npm run dev         # start dev server (localhost:3000)

npm start            # run the production build (after npm run build)

npm run test:watch   # vitest watch mode
```

Run a single test file: `npx vitest run lib/dosey.test.ts`

CI (`.github/workflows/ci.yml`) runs lint → typecheck → test → build in that order on every push/PR to `main`.

## Architecture

**See [`CLAUDE.md`](./CLAUDE.md) for a detailed breakdown** of state flow, the timer's timestamp-driven design, goal persistence, and the Dosey chat proxy.

**Key architectural patterns:**
- **State:** Lives in `app/page.tsx` and flows down via props (timer state via `useReducer` over `lib/timer-machine.ts`); goals are queried independently via Convex live queries.
- **Timer:** Timestamp-driven, not tick-decremented — `remaining` is recomputed from wall-clock elapsed time on every `TICK` to stay accurate when backgrounded.
- **Goals:** Scoped by client-computed `date` field (`lib/date.ts`), not server-side rollover — switching days queries a different bucket.
- **Dosey Chat:** Thin Gemini proxy (`app/api/chat/route.ts`) that's stateless per request; history is held client-side and re-sent on every message.
- **Motion:** GSAP owns scroll-driven reveals and the Dosey mascot; Framer Motion owns micro-interactions (press/hover).
- **Design tokens:** Centralized in `tailwind.config.ts` ("Gelcap Pastel" world) and `lib/phase-theme.ts` for semantic sticker colors.

## Showcase assets

`showcase-assets/` holds marketing screenshots (portfolio card + Google Play phone/tablet listings) captured from a running local instance. Regenerate them by signing in to a dev account and screenshotting the desired viewport sizes; they aren't produced by any script.
